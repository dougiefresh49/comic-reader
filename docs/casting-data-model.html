Casting data model redesign

Spec for #413 "Casting data model redesign: one home for each fact (spec and roundtable)". Revised twice on 2026-10-04 after two roundtable rounds; the record is at the end. Counts were read from the production database on 2026-10-03.

Summary

The character, cast and voice tables carry four generations of schema at once. The ElevenLabs voice id is stored in three tables. The castlist is keyed by the character's text name. The id columns added on 2026-09-30 were never filled: bubbles.character_id is empty on every bubble and voices.character_id on all 88 voices. Most of the owner questions from the last few days trace back to code keeping those copies in step.

The redesign gives each fact one home and links everything by id:

  • A character is an identity. It belongs to a franchise and can be a form of another character.
  • A work is one movie, show, game or comic run. An appearance says who voiced a character in a work.
  • A voice is something we have or have asked for. It is the only place the ElevenLabs id lives.
  • The castlist says which voice a character uses in an issue. It holds ids and two flags.

No bubble, page, panel, audio file or timestamp is deleted. Issues 1 and 2 keep playing throughout. No step calls Gemini, ElevenLabs or Roboflow.

The rules

These are what a builder checks its work against. Each is enforced by the database or a lint entry once the last issue lands.

#RuleEnforced by
R1The ElevenLabs voice id is stored in voices.current_elevenlabs_id and nowhere else.The other two columns are dropped.
R2Characters, voices, works and appearances are linked by id. No code looks up a character or a voice by its display name, except the alias resolver turning outside text into an id.Foreign keys; the text key columns are dropped.
R3A castlist row is (book_id, issue_id, character_id) plus a voice reference and two flags. Archive and restore never write to it.Primary key; lint entry limits .from("castlist") to src/lib/cast.ts.

R6One alias store: the aliases table, keyed on character_id.characters.aliases and aliases.canonical are dropped.
R7An appearance holds facts about the world (character, work, actor). A voice holds what we own (clip, prompt, slot). Neither repeats the other's columns.The old appearances table is dropped; the new one has no voice columns.

How it works after

Rendering a bubble

  1. Read bubbles.character_id. Null: no audio, and the bubble is listed as unassigned.
  2. Look at this issue's castlist row for the character. If it has in_issue false, stop: no audio, and the bubble is listed as "speaker removed from this issue". This is the one intended change from today, where in_issue is ignored.
  3. If that row has no_audio true, stop: no audio, by choice. It does not borrow from another issue.
  4. If that row has a voice, use it. If there is no row, or the row has no voice, use the latest issue's row in the book that has a voice. This is what voiceFor does today.
  5. Still no voice and the character has form_of: repeat steps 2 to 4 for that character, once.
  6. Read the voice row. status is active: render with current_elevenlabs_id. Otherwise the character is "cast, voice not in a slot", which the voices stop already shows.

Archive and restore

Both change one voices row and add or read one voice_archives row. Neither touches the castlist. A restored voice is picked up by every castlist row that references it, because they hold its uuid.

The earlier owner question (a restore overwriting a "no audio" marker) cannot occur: the flag is its own column and restore never writes to that table.

Picking a voice for a character

The picker for a character lists, in this order: voices for that character that are active, then archived (clip ready), then needs_clip, then appearances with no voice yet. Designed voices sit in the same list with no work beside them.

  1. New TMNT book, Leonardo. The owner picks "TMNT (2007)".
  2. No voice exists for that appearance, so one voices row is created with status = needs_clip, the character and the appearance. The castlist row references it.
  3. One casting_tasks row with action = clone targets that voice. That is the voice-lab to-do.
  4. The voice-lab import delivers the clip, keyed by character and work. The voice becomes archived (sample stored), and the voices stop can put it in a slot.

An appearance not in the list is added by hand (work, actor) or suggested by the existing lookup, which stays an optional action and writes facts only.

Forms and aliases

  • Use an alias when the text differs and nothing else does: "Leo", "Mikey", "Donnie".
  • Use a form (a second character row with form_of) when the pipeline must tell the two apart: a different face for face matching, or a different voice or voice mode. Batman and Bruce Wayne. Red Ranger and Jason.
  • A form with no voice of its own uses the voice of the character it points to. A form with its own castlist voice uses that.
  • Whether the existing rangers are split into civilian and morphed rows now is owner item O2. Until it is answered, existing rows are not split: "Zack Taylor" stays an alias of Black Ranger.

Voice-lab handoff

Today the import reads casting/<book>/cast.json from the voice-lab checkout. Rows carry a character name, a variant, a default flag, a file and a status. The import builds a display name "Character (variant)" and detects an already-imported row by its clip path. A second file, the ElevenLabs snapshot, fills description, labels and design prompt. Nothing reads the copies under data/casting/ in this repo.

Version 2 is one file per voice-lab book folder, casting/<folder>/voices.json in the voice-lab checkout. It has one row per voice and names things by id:

FieldRule
character_idRequired. Must exist in characters. A row with an unknown id is skipped with a message naming it. The import does not create characters.
voice_uuidOptional. When present, the row updates that voices row and no other matching is done. Use it for a voice that already exists here.
workPresent for a cloned voice. For a work that already exists, work.id is the id from the works table; for a new one it follows the title-and-year rule. The import upserts the work on its id, then the appearance on (character_id, work_id), then the voice on appearance_id.
design_promptPresent instead of work for a designed voice. The voice has no appearance and is matched on (character_id, md5).
file, md5Required for every row: the source clip of a clone, or the preview sample of a designed voice. Restore rebuilds a voice from this stored sample and refuses one without it. file is relative to clone-sources/<folder>/ in the voice-lab checkout. The clip is uploaded to the existing clips bucket with the md5 check, as today.
description, labelsRequired: the restore step refuses a voice without them. They replace the snapshot file's role.
starting_pickOptional, default false.
consumersOptional list. A new voice without it gets ["comic"]. On an existing voice a missing field leaves the column alone, and a present list is merged into what is there, never replacing it: room is what protects a shared voice from being archived (decision row 23). This replaces the room-characters file.
statusRows with approved or ready to clone are imported, as today. Others are skipped.
  • A voice in needs_clip for the same appearance receives the clip and becomes archived (sample stored).
  • No absolute path appears in the file. Paths are relative to the folder.
  • Voice-lab needs to write version 2. This repo never edits the voice-lab checkout; P5's PR carries the ask for the voice-lab thread, with this section as its spec.
  • The 59 voices already imported are linked by the backfill, so the import does not need to read version 1 again.
  • #316 "data/casting/tmnt-x-mmpr commits a local absolute path and clone-source file names in a public repo" is about the files already committed here. It is unchanged by this spec and continues on its own.

Delivery: six issues, one at a time

Three phases: add, switch, drop. The six issues run in order, P1 to P6, and only one is in flight at a time. The files in this area overlap too much to split between parallel agents: src/lib/cast.ts, src/lib/voice-requests.ts, src/lib/voices-registry.ts and src/workflows/steps/audio-plan.ts each touch the castlist, the voices, the aliases and the old appearances table. A sweep on 2026-10-03 found 75 files in src/ and scripts/ that reference these tables.

So an issue is not defined by a file list. It is defined by the names it removes. Its builder may edit any file in src/ and scripts/ that uses those names, and its gate is a repo-wide grep for them. Nothing is left unowned, because every dropped name belongs to exactly one issue:

Common to every issue:

  • Name gate. Two checks, because a bare column name such as voice_id also belongs to tables that stay. First, the builder deletes the issue's columns from its local copy of src/types/database.ts, runs pnpm typecheck until it is clean, and restores the file. Second, the PR lists every remaining grep hit for each name in src/ and scripts/ with the reason it stays (for example voice_archives.voice_id, or the ElevenLabs response field). Table names and constants (character_appearances, speaker_reviews, SKIPPED) must return no hits at all.
  • Repo gate. pnpm format:write, then pnpm typecheck, pnpm lint and pnpm format:check clean.
  • Scripts. A script that uses a removed name is converted if it has a package.json entry or an importer. A script with neither may be deleted; the PR lists each deletion with the grep that showed no entry and no importer.
  • Subagents are allowed inside an issue. The repo's rule on a fix round that doubles the diff still applies.
  • Migrations are written by the builder and applied by the lead. The builder does not regenerate types; the lead commits the regenerated src/types/database.ts to the issue's branch.
